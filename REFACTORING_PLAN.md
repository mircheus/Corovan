# Corovan — План рефакторинга

> Цель: превратить хаотичные скрипты в переиспользуемые модули с чёткими границами,
> единым контрактом сетевых сущностей и системой спавна — как фундамент под будущую
> рандомизацию уровня.
> Составлен: **2026-06-25**. Это план; код по нему пока не пишется.
> Связанные доки: `project_context.md`, `CLAUDE.md`.

---

## Принципы (применяются на всех фазах)

1. **Билд зелёный после каждой фазы.** Каждая фаза мерджится отдельно, проект компилируется и играется.
2. **Сначала контракты, потом перенос логики.** Сперва вводим интерфейс/компонент, потом по одному переводим потребителей, потом удаляем старое.
3. **Сетевые инварианты неприкосновенны** (см. `CLAUDE.md`): сервер валидирует мутации; `int` для HP/урона; `MovePosition` + ручная скорость, без `rb.linearVelocity`; child-NetworkBehaviour берёт identity через `GetComponentInParent`.
4. **Проверка после каждой фазы** в сценах `Road.unity` (основная) и `Drone_Testing.unity` — host + 1 клиент через ParrelSync.
5. **Чистка по ходу:** удалять оставленные `Debug.Log` (`ContainerLock`, `CarStopTrigger`, `Enemy`, `CarStopTrigger`) в затронутых файлах.

## Фаза D — Система спавна и каталог префабов (2–3 дня, риск: средний)

Фундамент под рандомизацию. Зависит от A (чистые контракты) и желательно B.

**Что вводим (`Scripts/Spawning/`):**
- `ISpawnable` + `NetworkObjectPool` — обобщение `BarrelSpawner` на любой сетевой префаб через Mirror custom spawn handlers (без постоянных Instantiate/Destroy).
- `NetworkPrefabCatalog` (ScriptableObject) — единый перечень спавнящихся префабов; на старте регистрируется в `CustomNetworkManager.spawnPrefabs` автоматически (убирает ручную рассинхронизацию).
- `SpawnPoint` / `SpawnZone` — маркеры мест в сцене (враги/лут/контейнеры/препятствия), с тегами категорий.
- `Spawner` (server-only) — общий компонент: «что, где, когда, сколько», использует пул и каталог.

**Шаги:**
1. Сделать `NetworkObjectPool` и перевести на него `BarrelSpawner` (доказать, что обобщение работает на существующем кейсе).
2. Ввести `NetworkPrefabCatalog`, перенести регистрацию спавн-префабов в него.
3. Добавить `SpawnPoint`/`SpawnZone`, расставить в `Road` для текущего контента (барабаны, враги, лут).
4. Перевести существующий спавн врагов/лута на `Spawner` (пока со статичными параметрами).

**Файлы:** `Spawning/*` (new); правки `BarrelSpawner`, `CustomNetworkManager`.

**Риски:** Mirror требует регистрации всех spawnable-префабов на клиенте и сервере одинаково; пул и кастомные spawn-хендлеры должны корректно ресетить состояние объекта при возврате (HP, активность, скорость).

**Контрольная точка:** весь текущий контент спавнится через общий механизм; добавление нового спавн-объекта = запись в каталог + префаб, без правок менеджера сети.

## Фаза G — Детерминированный генератор уровня (2–3 дня, риск: средний) — целевая

Собственно рандомизация поверх D+F.

**Что вводим (`Scripts/LevelGen/`):**
- `LevelDirector` (server-only): на старте раунда берёт `seed`, читает `SpawnTable`, расставляет контент по `SpawnZone` через `Spawner`/каталог.
- Синхронизация `seed` по сети (SyncVar/сообщение), чтобы хост и клиенты видели одинаковую раскладку.

**Шаги:**
1. Детерминированный RNG от `seed` (без `Math.random` в рантайме сети — единый источник на сервере, результат реплицируется спавном).
2. Алгоритм размещения: по зонам и весам из `SpawnTable`, с проверкой минимальных дистанций.
3. Хук в флоу старта раунда (после Фазы «match flow», если появится; иначе по началу сцены на сервере).

**Контрольная точка:** один и тот же seed даёт идентичную раскладку у всех; разные seed'ы — разные уровни; контент остаётся сетево-консистентным.
