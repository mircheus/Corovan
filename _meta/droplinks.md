# Drop Links: что учитывать при работе

Инструмент: **FPS Game → Navigation → Drop Links Generator**.
Он ищет края на запечённом NavMesh и ставит односторонние `NavMeshLink` (area `Jump`),
по которым зомби и дроиды спрыгивают вниз.

## Порядок работы

1. Запечь **все** `NavMeshSurface`, и верхние, и нижние.
2. Выставить настройки в окне (см. ниже).
3. Нажать **Generate**.
4. Проверить дуги в Scene view (Scene Preview).
5. Сохранить сцену.

## Запекание

- Каждый `NavMeshSurface` (Collect Objects = Children) запекает **только свои дочерние объекты**.
  Bake на верхней платформе не запекает пол под ней.
- Если внизу нет навмеша, ссылке некуда приземлиться: в отчёте будет `NoNavMeshBelow`.
- Верх и низ должны быть запечены для **одного Agent Type** (тот, что выбран в окне).
- После **каждого** перезапекания или изменения геометрии нужно заново нажать Generate.
  Ссылки привязаны к старому навмешу и сами не обновляются.

## Настройки

| Параметр | Что учитывать |
|---|---|
| **Min Drop** | Больше Step Height агента (Humanoid 0.75). Ниже этого агент и так спускается пешком. |
| **Max Drop** | Не меньше реального перепада высот. Если перепад больше, края не найдутся (`NoGroundBelow` / `TooDeep`). |
| **Max Forward** | Насколько далеко от края по горизонтали может быть точка приземления. |
| **Landing Clearance** | Зазор между телом и стеной уступа при приземлении. |
| **Obstacle Layers** | Должны включать пол и стены. Иначе лучи их не видят: пол «пропадает», а стены не мешают. |
| **Sample Spacing** | Шаг проверки вдоль края. Меньше значит точнее, но дольше. |
| **Max Link Width** | Длинные края режутся на несколько ссылок такой ширины. |
| **Bidirectional** | Выключено: только спрыгивание, запрыгивать нельзя. |
| **Only Selection Bounds** | Обрабатываются только края внутри bounds выделения (+1 / +2 / +1 м). |
| **Parent + Auto Update** | Только для движущихся платформ. |

Настройки хранятся в **EditorPrefs**, то есть на своём компьютере, а не в репозитории.
У другого разработчика будут свои значения.

## Generate и Clear

- Ссылки создаются под объектом `NavMesh Drop Links (generated)`.
  Generate **удаляет его и создаёт заново**, поэтому ручные правки внутри пропадут.
- Ручные `NavMeshLink` ставьте отдельно, вне этого объекта.
- Clear удаляет только сгенерированный объект.

## Если пишет «No drops found»

В окне есть список **Rejected samples**:

| Причина | Значит | Что делать |
|---|---|---|
| `NoGroundBelow` | Внизу ничего нет в пределах Max Drop | Увеличить Max Drop или добавить пол в Obstacle Layers |
| `TooDeep` | Пол есть, но глубже Max Drop | Увеличить Max Drop |
| `NoNavMeshBelow` | Пол есть, навмеша на нём нет | Запечь нижнюю поверхность |
| `TooShallow` | Перепад меньше Min Drop | Для внутренних краёв это нормально |
| `WallAhead` | За краем стена или перила | Обычно нормально |
| `LandingOffGround` | Ближайший навмеш внизу не там, куда падаем | Проверить геометрию внизу |
| `TooFar` | Точка приземления дальше Max Forward | Увеличить Max Forward |
| `OtherAgentType` | Край принадлежит навмешу другого агента | Выбрать нужный Agent Type |

- «The NavMesh is empty» значит, что навмеш не запечён вообще.
- «No NavMesh edge lies inside the selection bounds» значит, что выделение не накрывает края.

## Агенты

- На префабе врага должен быть `AgentLinkJumper`, тогда он прыгает по параболе.
  Сейчас он есть на `MeleeZombie` и `ShooterDroid`.
- Без компонента Unity просто «скользит» по ссылке по прямой.
- Прыжок работает только на сервере. Клиенты видят его через NetworkTransform.
- Настройки прыжка на компоненте:
  - `jumpHeight`: подскок над краем;
  - `gravity`: скорость падения;
  - `landingPause`: пауза после приземления.
- Чем выше перепад, тем дольше враг в воздухе: с 9 м это примерно 1 с.
  Для слишком высоких мест лучше поставить лестницу или пандус, а не повышать Max Drop.
- Стоимость area `Jump` = 2, поэтому агенты предпочитают пешие пути, если они не сильно длиннее.
